QuLam コンパイラ
=================

この文書は，qulam-compiler に実装されている QuLam コア言語の仕様をまとめたものです。

0. 全体像
---------

- コア言語は，改訂論文の自然演繹系 NQ に対応する QuLam の非算術的なコア体系です。
- 量子論理に基づく重要な規約として，ラムダ抽象は単一の引数のみをとり，他の環境を仮定してはいけません。
- 積は二項積のみを持ちます。n 項タプル `(t1, t2, t3, ...)` は，パーサで右結合の入れ子ペアに展開します。
- パーサは以下のような syntactic sugarを提供します。
  - n 項タプル `(t1, t2, t3, ...)`
  - `let x = e1 in e2`

syntactic sugar はすべてパーサの中でコア項に展開されます。


1. 型
-----

1.1 型の文法

型は次の文法で生成されます。

  Type ::= TyVar
         | Bot
         | Type * Type
         | Type -> Type

- 型変数 (TyVar):
  - 先頭にアポストロフィを付けた英数字列
  - 例: `'a`, `'x1`, `'state`

- Bot:
  - bottom 型，文字列 `"Bot"`

- 二項積:
  - `"A * B"` の形
  - 右結合 (A * B * C は A * (B * C) と解釈)

- 関数型:
  - `"A -> B"` の形
  - 右結合 (A -> B -> C は A -> (B -> C) と解釈)

1.2 型パーサの挙動

- 型変数: "'a", "'foo" など
- 定数: "Bot"
- 積: "A * B"
- 矢印: "A -> B"
- 括弧によって結合順を明示できます。例: "(A * B) -> C", "A * (B * C)"


2. 項
-----

2.1 項の文法

コア言語の項は次の構成子を持ちます。

  term ::= x                          -- 変数
         | \x : Type -> term          -- ラムダ抽象
         | term term                  -- 関数適用 (左結合)
         | (term, term)               -- 二項ペア
         | fst term                   -- 第 1 射影
         | snd term                   -- 第 2 射影
         | eps Type term              -- eps : Bot -> A
         | tau term term              -- 否定テスト / 制御
         | eta term                   -- 二重否定除去
         | theta term                 -- 二重否定導入
         | zeta term                  -- Sasaki hook の導入
         | xi term                    -- Sasaki hook の除去

実際の具体構文は以下のとおりです。

- 変数:
  - 先頭が小文字の英字で，後ろに英数字またはアンダースコアが続く識別子
  - 例: x, y1, state, f

- ラムダ抽象:
  - `\x : A -> t`
  - 引数は常に 1 個，型注釈も 1 つ
  - ボディ t は項

- 関数適用:
  - `"f x y"` は `"(f x) y"` と解釈されます (左結合)

- 二項ペア:
  - `"(t1, t2)"` は Pair t1 t2 に対応

- 射影:
  - `"fst t"`
  - `"snd t"`

- eps:
  - `"eps A t"`
    - A は型式
    - t は型 Bot の項 (型付け規則は後述)

- tau:
  - `"tau m n"`

- eta / theta:
  - `"eta t"`
  - `"theta t"`

- zeta / xi:
  - "zeta t"
  - "xi t"


2.2 予約語

次は変数名として使用できない予約語です。

  let, in, eps, tau, eta, theta, zeta, xi, fst, snd


3. 型付け
---------

3.1 型付けの環境

- 型付けの環境 Gamma は有限列

    x1 : A1
    x2 : A2
    ...
    xn : An

  からなります。

- 実装では Haskell の (String, Type) のリストです。
- 同じ変数名が複数回出現した場合は，パーサがエラーを返します。


3.2 型付け判断

記法:

  Gamma |- t : A

実装では関数:

  typeOf :: Context -> Term -> Either TypeError Type

として与えられています。

3.3 コア規則 (概略)

実装は QuLam 論文の自然演繹 / 型付け規則に従っています。ここでは概略だけ述べます。

- 変数:

  Gamma に (x : A) が含まれていれば Gamma |- x : A.

- ラムダ抽象:

  ラムダ項は `\x : A -> t` の形です。

  1) t を 1 変数環境 [x : A] のもとで型付けする。
  2) t の自由変数集合を計算し，{x} 以外の自由変数が存在しないことを確認する。
     - 他の自由変数があれば，型エラー "Lambda is not closed; free variable: ..." を出す。
  3) t の型が B であれば，ラムダ抽象全体の型は A -> B.

  重要なのは，「外部環境 Gamma はラムダの型付けには使われない」という点です。すなわち，ラムダは「仮引数以外をキャプチャしない閉じた関数」となります。

- 関数適用:

  Gamma |- f : A -> B, Gamma |- u : A なら Gamma |- f u : B.

  実装上は，同じ環境 Gamma を f と u の両方に渡しています (弱化を許す形)。

- ペア:

  Gamma |- t1 : A, Gamma |- t2 : B なら Gamma |- (t1, t2) : A * B.

- fst / snd:

  Gamma |- p : A * B なら
  - Gamma |- fst p : A
  - Gamma |- snd p : B

- eps:

  Gamma |- m : Bot, A が任意の型のとき，Gamma |- eps A m : A.

- tau:

  意図される型は

    tau : (A -> B) -> (B -> Bot) -> (A -> Bot)

  です。実装では Bot と矢印型を用いてこの構造が保たれるように型チェックしています。

- eta:

  eta : ((A -> Bot) -> Bot) -> A

- theta:

  theta : A -> (A -> Bot) -> Bot

- zeta:

  zeta : ((A * ((A * B) -> Bot)) -> Bot) -> (A -> B)

- xi:

  xi : (A -> B) -> ((A * ((A * B) -> Bot)) -> Bot)

3.4 ラムダ抽象が「閉じていること」の検査

上で述べたように，実装ではすべてのラムダ抽象が「仮引数以外の自由変数を持たない」ことを強制しています。

- `\x : A -> t` を型付けする際:

  - t を [x : A] のもとで型付け
  - t の自由変数集合 FV(t) を計算
  - FV(t) \ {x} が空集合でなければエラー

すなわち，「外部環境をキャプチャするラムダ」は QuLam の項として認められません。複数の引数を渡したい場合は，A * B * ... のような積型で一つのタプル引数にまとめる必要があります。


4. 操作的意味論
----------------

実装では 1 ステップ簡約 (step) を定義し，これを繰り返して正規形 (nf) を求めます。


4.1 redex の種類

基本的な redex は以下のとおりです。

- beta:

  `(\x : A -> t) u` は `t[x := u]` に簡約されます。

- ペアの射影:

  `fst (t1, t2)` は `t1` に簡約  
  `snd (t1, t2)` は `t2` に簡約

- eta / theta:

  `eta (theta t)` は `t` に簡約

4.2 正規形

- 上記のような redex がどこにも含まれない項を正規形と呼びます。
- nf 関数は，これらの規則が適用できなくなるまで 1 ステップ簡約を繰り返し，正規形を返します。


5. パーサ側のsyntactic sugar
-----------------------------

以下はすべて「パーサでコア項に展開される syntactic sugar」です。typeOf や nf が扱うのは展開後のコア項です。


5.1 n 項タプル

具体構文:

  (t1, t2)
  (t1, t2, t3)
  (t1, t2, t3, t4)
  ...

展開規則:

- 項列 [t1, t2, ..., tn] (n >= 1) に対して:

  mkTuple [t1]          = t1
  mkTuple [t1, t2]      = (t1, t2)
  mkTuple [t1, t2, t3]  = (t1, (t2, t3))
  mkTuple [t1, t2, t3, t4] = (t1, (t2, (t3, t4)))

したがって，

  (x, y, z)

は

  (x, (y, z))

としてコア項に落ちます。


5.2 let 構文

具体構文 (変数 1 個のみ):

  let x = e1 in e2

展開規則:

- パース時に，beta と同じ置換を用いて

  e2[x := e1]

に展開します。

実装では，beta 簡約に用いている `subst` 関数をそのまま使います。そのため，let はコア構文としては存在せず，純粋なマクロです。

ネストした let も書けます。例えば:

  let u = (x, y) in
  let v = fst u in
    v

は展開後，

  fst (x, y)

となります。x : 'a，y : 'b の場合，展開後の項の型は 'a，正規形は x です。


6. ファイル形式とコマンドライン
--------------------------------

6.1 ファイル形式 (.qlam)

コンパイラは次のような形式のソースファイルを読み込みます。

  context:
    x : A
    y : B
    ...

  term:
    t

注意:

- "context:" と "term:" は固定のキーワードです。
- コンテキスト (環境) は `"名前 : 型"` の形式です。
- 項 t は複数行に渡っても構いません。インデントはトークン化に影響しない範囲で自由です。
- 行コメントは `"--"` から行末までです。

例:

  context:
    x : 'a
    y : 'b
    z : 'c

  term:
    fst (snd (x, y, z))


6.2 コマンドラインの使い方

プロジェクトルートで次を実行します。

  stack run qulam-compiler

ソースファイルを指定する場合:

  stack run qulam-compiler -- foo.qlam

引数なしの場合は，恒等関数を使った組み込みデモを実行します。

ソースファイルを指定した場合は，ソース，環境，項を表示し，
型検査が成功すれば型と正規形を表示します。
ソースファイル以外の追加引数は受け付けません。

例: example.qlam

  context:
    x : 'a
    y : 'b

  term:
    fst (x, y)

実行:

  stack run qulam-compiler -- example.qlam

出力（要約）:

  [type]
    'a
  [nf]
    x
