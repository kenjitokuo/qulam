QuLam compiler
=================

This document summarizes the specification of the QuLam core language implemented in qulam-compiler.

0. Overview
-----------

- The compiler implements the non-arithmetic QuLam core language corresponding to the revised paper and the natural deduction system NQ for quantum logic.
- As an important convention based on quantum logic, a lambda abstraction takes only a single argument and must not assume any other environment.
- The language has only binary products. An n-ary tuple (t1, t2, t3, ...) is expanded by the parser into a right-associated nested pair.
- The parser provides the following syntactic sugar:
  - n-ary tuples (t1, t2, t3, ...)
  - let x = e1 in e2

All syntactic sugar is expanded into core terms inside the parser.


1. Types
--------

1.1 Grammar of types

Types are generated by the following grammar.

  Type ::= TyVar
         | Bot
         | Type * Type
         | Type -> Type

- Type variables (TyVar):
  - An alphanumeric string with a leading apostrophe.
  - Examples: 'a, 'x1, 'state

- Bot:
  - The bottom type, written as the string "Bot".

- Binary product:
  - The form "A * B".
  - Right-associative (A * B * C is interpreted as A * (B * C)).

- Function type:
  - The form "A -> B".
  - Right-associative (A -> B -> C is interpreted as A -> (B -> C)).

1.2 Behavior of the type parser

- Type variables: 'a, 'foo, etc.
- Constants: "Bot"
- Product types: "A * B"
- Arrow types: "A -> B"
- Parentheses can be used to make the order of association explicit. Examples: "(A * B) -> C", "A * (B * C)".


2. Terms
--------

2.1 Grammar of terms

Core language terms have the following constructors.

  term ::= x                          -- variable
         | \x : Type -> term         -- lambda abstraction
         | term term                  -- function application (left-associative)
         | (term, term)               -- binary pair
         | fst term                   -- first projection
         | snd term                   -- second projection
         | eps Type term              -- eps : Bot -> A
         | tau term term              -- negative test / control
         | eta term                   -- double negation elimination
         | theta term                 -- double negation introduction
         | zeta term                  -- Sasaki hook introduction
         | xi term                    -- Sasaki hook elimination

The concrete syntax is as follows.

- Variables:
  - Identifiers starting with a lowercase English letter, followed by alphanumeric characters or underscores.
  - Examples: x, y1, state, f

- Lambda abstraction:
  - \x : A -> t
  - The parameter is always a single variable with a single type annotation.
  - The body t is a term.

- Function application:
  - f x y is interpreted as (f x) y (left-associative).

- Binary pair:
  - (t1, t2) corresponds to the pair of t1 and t2.

- Projections:
  - fst t
  - snd t

- eps:
  - eps A t
    - A is a type expression.
    - t is a term of type Bot (the typing rules are described later).

- tau:
  - tau m n

- eta / theta:
  - eta t
  - theta t

- zeta / xi:
  - zeta t
  - xi t

2.2 Reserved words

The following are reserved words and cannot be used as variable names.

  let, in, eps, tau, eta, theta, zeta, xi, fst, snd


3. Typing
---------

3.1 Typing environment

- A typing environment Gamma is a finite partial map, written as distinct variable declarations:

    x1 : A1
    x2 : A2
    ...
    xn : An

- In the implementation, this is a Haskell list of (String, Type).
- Duplicate variable names are rejected by the parser.


3.2 Typing judgment

Notation:

  Gamma |- t : A

In the implementation, typing is given by the function

  typeOf :: Context -> Term -> Either TypeError Type


3.3 Core rules (outline)

The implementation follows the natural deduction and typing rules of the QuLam paper. Only an outline is given here.

- Variable:

  If Gamma contains (x : A), then Gamma |- x : A.

- Lambda abstraction:

  A lambda term has the form \x : A -> t.

  1) Type t under the single-variable environment [x : A].
  2) Compute the set of free variables of t and check that there are no free variables other than x.
     - If there are other free variables, a type error "Lambda is not closed; free variable: ..." is reported.
  3) If the type of t is B, then the type of the whole lambda abstraction is A -> B.

  The important point is that the external environment Gamma is not used in typing the lambda. In other words, a lambda is a closed function that does not capture variables other than its formal parameter.

- Function application:

  If Gamma |- f : A -> B and Gamma |- u : A, then Gamma |- f u : B.

  In the implementation, the same environment Gamma is passed to both f and u (allowing weakening).

- Pair:

  If Gamma |- t1 : A and Gamma |- t2 : B, then Gamma |- (t1, t2) : A * B.

- fst / snd:

  If Gamma |- p : A * B, then
  - Gamma |- fst p : A
  - Gamma |- snd p : B

- eps:

  If Gamma |- m : Bot and A is any type, then Gamma |- eps A m : A.

- tau:

  The intended type of tau is

    tau : (A -> B) -> (B -> Bot) -> (A -> Bot).

  In the implementation, type checking ensures that this structure is preserved using Bot and arrow types.

- eta:

  eta : ((A -> Bot) -> Bot) -> A

- theta:

  theta : A -> (A -> Bot) -> Bot

- zeta:

  zeta : ((A * ((A * B) -> Bot)) -> Bot) -> (A -> B)

- xi:

  xi : (A -> B) -> ((A * ((A * B) -> Bot)) -> Bot)

3.4 Checking that lambda abstractions are closed

As mentioned above, the implementation enforces that every lambda abstraction has no free variables other than its parameter.

- To type \x : A -> t:

  - Type t under [x : A].
  - Compute the set of free variables FV(t).
  - If FV(t) minus {x} is nonempty, it is an error.

In other words, lambda abstractions that capture the external environment are not allowed as QuLam terms. If you want to pass multiple arguments, you must pack them into a single tuple argument using a product type such as A * B * ... .


4. Operational semantics
------------------------

The implementation defines one-step reduction (step) and repeats it to obtain a normal form (nf).


4.1 Kinds of redexes

The basic redexes are as follows.

- Beta:

  (\x : A -> t) u reduces to t[x := u].

- Projections of pairs:

  fst (t1, t2) reduces to t1.
  snd (t1, t2) reduces to t2.

- eta / theta:

  eta (theta t) reduces to t.

4.2 Normal forms

- A term that contains none of the above redexes is called a normal form.
- The function nf repeatedly applies one-step reduction until no rules apply and returns a normal form.


5. Syntactic sugar in the parser
--------------------------------

The following are syntactic sugar constructs that the parser expands into core terms. The functions typeOf and nf always operate on the expanded core terms.


5.1 N-ary tuples

Concrete syntax:

  (t1, t2)
  (t1, t2, t3)
  (t1, t2, t3, t4)
  ...

Expansion rule:

- For a list of terms [t1, t2, ..., tn] (n >= 1):

  mkTuple [t1]             = t1
  mkTuple [t1, t2]         = (t1, t2)
  mkTuple [t1, t2, t3]     = (t1, (t2, t3))
  mkTuple [t1, t2, t3, t4] = (t1, (t2, (t3, t4)))

Therefore,

  (x, y, z)

is translated to

  (x, (y, z))

as a core term.


5.2 let syntax

Concrete syntax (for a single variable):

  let x = e1 in e2

Expansion rule:

- At parse time, this is expanded using the same substitution as beta reduction:

  e2[x := e1].

In the implementation, the subst function used for beta reduction is reused as is. Therefore, let is not a core construct and is a pure macro.

Nested lets can also be written. For example:

  let u = (x, y) in
  let v = fst u in
    v

is expanded to

  fst (x, y).

If x : 'a and y : 'b, the expanded term has type 'a and normal form x.


6. File format and command line
-------------------------------

6.1 File format (.qlam)

The compiler reads source files of the following form.

  context:
    x : A
    y : B
    ...

  term:
    t

Notes:

- context: and term: are fixed keywords.
- The context (environment) is written as name : type.
- The term t may span multiple lines. Indentation is free as long as it does not affect tokenization.
- A line comment starts with -- and continues to the end of the line.

Example:

  context:
    x : 'a
    y : 'b
    z : 'c

  term:
    fst (snd (x, y, z))


6.2 Command line usage

From the project root:

  stack run qulam-compiler

or, to process a source file:

  stack run qulam-compiler -- foo.qlam

There are two modes.

1) Without arguments, the compiler runs a built-in demonstration of the identity function and its type.

2) With a source file, the compiler parses it into a typing context and a term. It prints the source, context, term, inferred type, and normal form (when type checking succeeds).

Only one source-file argument is accepted. Extra command-line arguments are rejected.

Example example.qlam:

  context:
    x : 'a
    y : 'b

  term:
    fst (x, y)

Command:

  stack run qulam-compiler -- example.qlam

Expected result (summary):

  [type]
    'a
  [nf]
    x
